# TaskTracker

Персональный трекер задач «TaskTracker» — SPA для учёта задач по проектам с отслеживанием
рабочего времени и формированием отчётов для выставления счетов.

## Стек

- Vue 3 (Composition API, `<script setup>`)
- Pinia — хранилище состояния
- Vue Router — маршрутизация
- Vite — сборка
- xlsx (SheetJS) — экспорт в Excel
- Vitest — тесты логики таймера, хранилища и серверной авторизации
- Vercel Serverless Function — серверная проверка пароля администратора

## Роли доступа

При входе приложение показывает окно «Выберите вашу роль» (закрыть его без выбора нельзя):

- **Гость** — просмотр проектов, доски задач, экрана «Все задачи», отчётов и выгрузка XLSX,
  скачивание резервной копии. Без добавления, редактирования, удаления и таймера.
- **Администратор** — полный доступ; при выборе роли запрашивается пароль.

Пароль **не попадает в клиентский бандл**: он передаётся на сервер (`POST /api/login`),
где сравнивается со scrypt-хешем из серверной переменной окружения `ADMIN_PASSWORD_HASH`
(без префикса `VITE_`). Дополнительно работает ограничение на число попыток входа.

Выбранная роль хранится в `localStorage` (ключ `tasktracker_role`), сменить её можно кнопкой
«Выйти» в шапке.

> **Ограничение.** Проверка пароля — серверная, поэтому узнать его нельзя. Но данные
> приложения лежат в `localStorage` браузера, а роль хранится на клиенте. Это означает, что
> (1) разграничение прав — на уровне интерфейса, и (2) каждый браузер видит **свою** копию
> данных. Чтобы гость на другом устройстве видел ваши задачи, нужен серверный бэкенд
> (см. «Возможные улучшения» в `PLAN.md`).

## Запуск

```bash
npm install

# 1. Хеш пароля администратора
npm run hash-password -- "ваш пароль"
#    → ADMIN_PASSWORD_HASH=scrypt$...

# 2. Файл .env (не коммитится) — скопируйте .env.example и вставьте полученное значение
#    ADMIN_PASSWORD_HASH=scrypt$...

npm run dev      # режим разработки
npm run build    # production-сборка в dist/
npm run preview  # просмотр собранной версии
npm test         # тесты
```

`npm run dev` поднимает тот же эндпоинт `/api/login`, что и Vercel, поэтому вход
администратора работает локально без установки Vercel CLI. Если `ADMIN_PASSWORD_HASH`
не задан, сервер выведет предупреждение, а вход в роли администратора будет недоступен
(гость работает всегда).

## Функциональность

- **Проекты** (`/`): боковая навигация, добавление/редактирование проекта (название + часовая ставка).
- **Доска задач** (`/project/:id`): карточки задач, фильтры по статусам, модальное окно задачи,
  удаление задачи с подтверждением.
- **Все задачи** (`/tasks`): единый список по всем проектам с фильтрами по проекту, статусу
  и приоритету, поиском по названию и сводкой по времени.
- **Отчёт** (`/report`): выбор проекта и диапазона дат, превью таблицы, выгрузка XLSX.
- **Таймер**: `setInterval` 1 с, накопление времени сессиями, авто-пауза параллельной задачи
  с уведомлением, восстановление таймера при перезагрузке страницы.
- **Хранение**: `localStorage`, ключ `tasktracker_data`, запись с debounce (2 с) и страховкой
  раз в 5 секунд, при закрытии/скрытии вкладки.
- **Резервные копии**: «Скачать бэкап» в футере (JSON); «Загрузить бэкап» — только у админа.

## Решения по интерпретации ТЗ

- **Фильтр «Активные»** = задачи со статусом `todo` + `in_progress` (все незавершённые,
  кроме «На паузе»).
- **Время в отчёте** — часы с округлением до 2 знаков после запятой (не шаг 15 минут).
- **Приоритет новой задачи по умолчанию** — «Средний» (жёлтый).
- **Ставка по умолчанию** — 3000 руб/час (редактируется при создании и после).
- **Дизайн-токены** определены по описанию дизайн-системы «Post-Digital Archive» из ТЗ
  (JSON дизайн-системы не был приложен): сетка 3 колонки, container 1440px, карточки с
  чёрной рамкой 1px и радиусом 0, uppercase-типографика с tracking, чёрные кнопки,
  таблицы без вертикальных линий.

## Деплой на Vercel

Проект состоит из статического SPA (`dist/`) и serverless-функции проверки пароля
(`api/login.js`), поэтому деплоить нужно именно на Vercel (или аналог с поддержкой
serverless-функций). При публикации только содержимого `dist/` на статическом хостинге
вход администратора работать не будет — это осознанное поведение «fail closed».

1. **Переменная окружения.** В панели Vercel → Settings → Environment Variables добавьте:

   | Имя | Значение |
   | --- | --- |
   | `ADMIN_PASSWORD_HASH` | результат `npm run hash-password -- "ваш пароль"` |

   Префикс `VITE_` добавлять нельзя: без него переменная доступна только функции на сервере
   и не попадает в браузер.

2. **Деплой.** Через панель (Import Git Repository) или CLI:

   ```bash
   npm i -g vercel
   vercel            # первый деплой
   vercel --prod     # продакшен
   ```

   Framework Preset — Vite, Build Command — `npm run build`, Output Directory — `dist`
   (уже зафиксировано в `vercel.json`).

3. **После смены пароля** нужен redeploy: значение переменной подставляется в серверную
   функцию при сборке.

4. **Проверка после деплоя.** Открыть корневой URL → появится окно выбора роли; вход гостем
   работает без пароля; вход администратором с вашим паролем открывает полный доступ;
   неверный пароль даёт «Неверный пароль»; прямой переход на `/report` и F5 не дают 404.

**Локальная проверка продакшен-сборки**

```bash
npm run build
npm run preview
```

Полное руководство, модель безопасности и рекомендации по развитию — в `PLAN.md`.
